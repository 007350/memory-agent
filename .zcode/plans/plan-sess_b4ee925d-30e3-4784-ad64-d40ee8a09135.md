# 记忆系统全面升级计划

## 现状结论（为什么改）

当前记忆是"双层 SQLite + 关键词检索"：会话级 Q&A 记忆 + 用户级画像/事件流，读写分别挂在 LangGraph 的 `memory_retrieval`/`memory_update` 两端。核心问题是**检索对中文失效**（空格分词退化成 0/1 匹配、`relevance` 字段从未更新却占 60% 权重）、**伪总结 bug 污染事件表**（画像≥6 字段后每轮追加一条写死字符串的 summary 事件）、facts 跨轮重复入库、无时间衰减、prompt 注入无预算。仓库里已有现成的硅基流动 Qwen3-Embedding-8B API（`lightrag/.env`），可直接复用做语义检索。

## 改动内容

### 1. 新增 embedding 服务（语义检索基础）
- 新建 `backend/app/services/embedding_service.py`：OpenAI 兼容 `/embeddings` 调用，带内存缓存与失败降级（失败返回 None，检索自动退回关键词模式——与项目 LightRAG 降级哲学一致）
- `backend/app/config.py` + `backend/.env.example` / `.env` 新增：`EMBEDDING_BASE_URL`（硅基流动）、`EMBEDDING_API_KEY`、`EMBEDDING_MODEL=Qwen/Qwen3-Embedding-8B`、`MEMORY_SEMANTIC_TOP_K=20`、`MEMORY_DECAY_HALF_LIFE_DAYS=14`、`MEMORY_CONTEXT_BUDGET_CHARS=3000`

### 2. memory_service 存储层升级（`backend/app/services/memory_service.py`）
- `memory_events` 表新增 `embedding` 列（BLOB，float32 bytes），带 `_migrate` 补列逻辑（老数据 embedding 为空则只走关键词打分）
- `save_structured_memory` 写事件时异步补算 embedding
- 新增：跨轮查重 `find_existing_events(user_id, contents)`（归一化后比对）、过期事件清理 `purge_expired_events()`

### 3. 重写读链路（`backend/app/graph/nodes.py` `node_memory_retrieval` + `_score_relevance`）
- 混合打分：**语义余弦相似度**（0.55）+ **中文字符 bigram 关键词覆盖**（0.25，修复中文匹配）+ importance（0.1）+ **时间衰减** `0.5 ** (age_days/half_life)`（0.1）+ 反馈分加成；删除死的 `relevance` 字段权重
- embedding 不可用时自动整体退化为关键词路径
- 检索完顺带调用 `purge_expired_events()` 惰性清理

### 4. 重写写链路（`node_memory_update`）
- **提取模型降级**：主力模型 → `llm_model_light`（step-3.5-flash），加 1 次重试，JSON 解析失败记 warning 不再静默
- **修复伪总结 bug**：仅当画像字段本轮实际发生变化时才触发摘要，摘要内容由轻量模型真实生成（替换 profile["summary"]），旧的 profile_summary 事件标记过期而非无限追加
- **facts 跨轮去重**：写库前查 DB 归一化 content，已存在则跳过（同步更新 `test_memory_service.py` 中固化旧行为的断言）
- **画像冲突留痕**：值变化才写 profile_update 事件，metadata 记 previous_value
- conversation 记忆截断 500 → 1000 字符

### 5. Token 预算 + 记忆溯源链路
- `_build_messages_with_memory`（`knowledge_agent.py:34`，被 general/coding 复用）：按"画像→事件→近期对话"优先级注入，总预算 `MEMORY_CONTEXT_BUDGET_CHARS`（默认 3000 字符），事件单条截 200 字符，按分数从高到低填充；返回 `(messages, used_memories)`
- `AgentState`/`ChatResponse` 增加 `used_memories`（id、event_type、content 摘要、score），chat 路由返回给前端

### 6. 前端展示（`frontend/src`）
- `api.ts`：ChatResponse 类型加 `used_memories`
- `ChatPage.tsx`：气泡 meta 区加"参考了 N 条记忆"徽章，可展开查看列表；顺带移除永远为空的 `getMemory(userId)` 冗余调用（隐式耦合 bug）

### 7. 测试与验证
- 更新 `test_memory_service.py`（去重行为、embedding 列）、`test_nodes.py`（新打分公式、中文 bigram、时间衰减）
- 新增 `test_embedding_service.py`（mock HTTP）；补 `node_memory_update` 测试（目前完全空白，mock LLM）
- `pytest` 全绿后跑 `tests/evaluation/eval_rag.py` 30 题回归，对比 eval_results.json 确认无退化
- 手动起服务验证：中文记忆召回、伪总结不再增殖、气泡徽章正常显示

## 实施顺序

1. 配置 + embedding_service → 2. memory_service 存储层 → 3. nodes.py 读写链路 → 4. agent 预算/溯源 → 5. 路由/Schema → 6. 前端 → 7. 测试 + 评测回归

## 风险与边界

- 老事件无 embedding：打分自动降级关键词路径，不做全量回填（新写入的记忆才有向量）
- 硅基流动 key 直接复用 lightrag/.env 中已有的那份写入 backend/.env
- 不改 REST API 路径（只加响应字段），前端记忆面板现有功能不受影响
